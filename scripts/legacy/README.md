# legacy 脚本归档

这些脚本是开发过程中的一次性诊断、验证与数据准备工具，**不属于项目运行链路**，也不被 `tests/` 或 `app/` 引用。保留在此仅为可追溯。

## 为什么归档而不是删除

它们记录了各阶段的排查过程（检索排名诊断、权限过滤验证、跨格式解析试验等），回溯问题时可能有参考价值。但它们不适合留在 `scripts/` 根目录：

- 依赖当时的数据集与目录结构，**现在多半无法直接运行**
- 命名混乱（`debug_*` / `verify_*` / `test_*` 混用），干扰阅读
- 与 `tests/` 下的自动化测试职责重叠，容易被误认为它们是测试

## 目录内容

| 前缀 | 用途 |
|---|---|
| `debug_*` | 特定问题的现场诊断（检索排名、元数据、DOCX 分块） |
| `verify_*` | 某次优化的效果验证（缓存命中、权限过滤回归） |
| `test_*` / `run_*` | 一次性功能试验，非自动化测试 |
| `gen_*` / `create_*` / `write_*` / `download_*` | 测试数据准备 |
| `p1_demo.py` | 阶段一薄切片端到端演示例程 |

## 相关去处

- **自动化测试**：`tests/`（208 个用例，已接入 CI，含覆盖率门禁）
- **日常运维脚本**：`scripts/` 根目录（见仓库根目录 `README.md`）
